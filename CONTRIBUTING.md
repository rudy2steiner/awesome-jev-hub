# Contributing to Awesome Jev Hub

Thank you for helping make Jev resources easier to discover and evaluate. Awesome Jev Hub is a curated shortlist, not an exhaustive catalog, so every submission is reviewed for relevance, usefulness, and evidence.

## Two Ways to Submit

### Recommend a Resource

Use the [resource submission form](https://github.com/rudy2steiner/awesome-jev-hub/issues/new?template=resource.yml) if you do not want to edit Markdown. Choose an existing category and provide the requested evidence. A maintainer will place an accepted resource in the list.

### Open a Pull Request

Experienced contributors may edit `README.md` directly:

1. Search the README and closed issues or pull requests for duplicates.
2. Choose one existing community category.
3. Add one resource in the required format.
4. Open a pull request and complete the checklist.

Do not create, rename, or reorganize categories in a resource submission. Open a separate issue if the taxonomy needs to change.

## Eligibility

A resource must meet all of these requirements:

- It is directly relevant to Jev, not merely to AI or language models in general.
- Its primary link is public and working.
- It is not already listed or awaiting review.
- It helps readers perform a concrete task, understand Jev, reproduce a result, or make an informed technical decision.
- Its submission includes evidence such as runnable code, a tested workflow, official documentation, reproducible measurements, or a clearly documented real-world experience.
- The description is factual and explains what the resource does; it is not marketing copy.
- The submitter discloses whether they created, maintain, work for, or are otherwise affiliated with the resource.

Early-stage work is welcome when it is usable and clearly labeled. GitHub stars are not an admission requirement.

## One Resource per Submission

Submit exactly one resource in each issue or pull request. This keeps review discussion focused and makes changes easy to merge or revert.

An entry uses this format:

```markdown
- [Resource Name](https://example.com) — Objective description of what it does and why it is useful.
```

Use an em dash (`—`), start the description with an uppercase letter, and end it with a period. Prefer a source repository or canonical page over an aggregator or tracking URL.

## Categories

Choose the single best existing category:

- Skills & Agents
- Developer Ecosystem
- Patterns & Cookbook
- Projects by Use Case
- Playgrounds & Reproducible Demos
- Benchmarks & Evidence
- Failures & Limitations
- Learn
- Open Alternatives
- Ecosystem Radar

`Official & Access`, `Recently Added`, and the introductory sections are maintained from first-party sources by repository maintainers.

## Evidence Expectations

Useful evidence depends on the resource type:

- **Skill or agent:** installation instructions, source code, and a concrete Jev workflow.
- **Project or integration:** runnable setup, supported versions, and an example input and output.
- **Pattern or tutorial:** prerequisites, complete steps, and the result readers should expect.
- **Benchmark:** dataset, model version, prompts or question definitions, metrics, and enough detail to reproduce the run.
- **Failure or limitation:** the setup, observed behavior, attempted mitigations, and whether the result was reproduced.
- **Ecosystem update:** a primary source and the date on which it was checked.

## Review Process

Maintainers review submissions for:

1. Correct format and category.
2. Duplicate links or substantially duplicate resources.
3. Direct Jev relevance.
4. Public accessibility and basic usability.
5. Evidence quality and disclosure of affiliation.
6. Clear, neutral English.

Passing automated checks means a submission is ready for editorial review; it does not guarantee inclusion. A maintainer may request changes, move an entry, defer an immature resource, or decline an item that does not improve the shortlist.

## Help Curate

You can contribute without submitting your own resource. Review open issues, test instructions, reproduce examples, report broken links, and add specific comments or reactions to submissions you have evaluated.
